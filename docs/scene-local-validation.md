## 已完成的验证

- Python 单元测试 49 项；前端/DUF/相机数学测试 22 项。
- Carry 配套动作：修正脚底 Root 与髋部旋转中心差异，以及 DSON 固定轴顺序到 THREE 内禀 Euler 顺序的转换；被抱人物从地面错位恢复到抱人者怀前。采用通用旋转中心公式，不按文件名或预览图硬编码偏移。
- 整体大小从 1.00 到 1.01、整体转身 1° 后，保存数据中两角色大小及角色间距离均为原来的 1.01 倍，各自局部骨骼姿势不变；整体撤销/重做恢复 0°/1°。
- 真实 X、Y、Z 箭头拖动均同步右侧数值；Y 拖动仅修改上下（-1.7→-0.5），Z 拖动仅修改前后（-1.3→0.4），其余两轴不变。浏览器未出现错误日志。
- 本地浏览器的 5 个角色按钮位于同一行；选中角色高亮，删除前出现编辑器内确认框，取消不删除；新增仍复用空编号。
- 场景与单角色分别命名保存到3D图库；完整场景确认恢复5个角色，单角色动作应用到选中槽位；应用到节点返回页面，重新打开恢复全部角色及当前槽位。
- 使用用户现有 `G8.1F_01_pose.duf` 实际选择文件导入成功；选择器的 accept 不设置，默认所有格式；导入后编辑器保持打开。
- 彩蛋、图库、3D图库切换互斥；3D图库不出现在另外两类内容下。
- 整组落地：5角色统一移动 `[0, 2.388328231753089, 0]`，各角色骨骼局部位置和旋转不变。蒙皮最低点 `-8.444328308105463`，地面 `-8.444328308105469`，浮点误差约 `6e-15`。
- 真实拖动视角球后转换到输出，全部10对角色距离最大误差约 `5.33e-15`；前端数学测试同时比较多个模型点的投影，误差小于 `1e-9`。
- 输出预览不含蓝色选择高亮和地面网格；编辑区/输出图宽高比不同，因此最终裁切以正面输出预览为准。

## 尚未覆盖 / 限制

- Carry 文件未含源骨架定义，虽然用户标为 G9，其通道使用 G3/G8 系列命名。按骨骼结构选择默认初始姿态，不能据此确认原模型版本；源体型、缩放、ERC 和骨架差异仍会影响接触点，未承诺逐关节完全复原。
- 尚未跑实际 Qwen/VNCCS 五人 GPU 生成；参考图身份一致性仍为实验性能力。
- Windows 文件窗口的“超大图标”无法由 HTML 指定，需用户在系统文件窗口中设置。
- 保存动作使用插件 JSON，可在本插件继续编辑；不提供 DAZ DUF 写回。
- 视角换算、整组落地及加载场景会重建人偶，清空会话内撤销记录；操作前可先保存场景。
